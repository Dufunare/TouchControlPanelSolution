# 固定设备坐标轴的相对平移遥控

## 需求与基线

用户确认 Touch 设备自身 XYZ 与其摆放方向一致，机械臂固定坐标系与实际物理移动一致。不再要求设备间空间点对标定。以早期视频分支 feat/relay-uvc-video-preview (55be40c) 的直接位置映射为意图基线；保留当前视频、3D、界面优化。不是将 Touch 绝对坐标直接当作机器人绝对坐标。

## 默认操作与离合

- 主区直接选择 Robot X/Y/Z 各自对应的 +/− Touch X/Y/Z（每个输入轴只用一次）。恢复早期分支轴向为 X←+Touch X、Y←−Touch Z、Z←+Touch Y；这只是已知代码基线，不是现场摆放方向的自动识别。用户需确认各物理方向和当前机器人 User/Tool 坐标约定。
- 移动比例 s 为位置比例，默认1×，既有可选范围0.05–4×保留；比例不是速度设定。默认每轴输入死区0，已有0.3mm重复目标过滤仍有效，可在高级区主动设置死区。
- Button1 按下时同时读取当前 Touch XYZ 样本和最近有效的机器人实际 TCP，保存 h0/r0 与本次配置。两者采集时钟独立，并非硬件同步测量。第一帧仅捕获，不下发目标。
- 按住期间，原始位置意图 r_goal = r0 + s M(h − h0)（每轴死区非0时在比例之前做原有对称死区）。M 为带符号的轴置换矩阵。保持捕获的实际机器人 RPY，不引入 Touch 笔姿态、旧空间标定矩阵或 GL 显示原点。
- **master 式直接位置**：每周期由当前 Touch 和本次离合锚点直接计算目标，加上保护层此前丢弃位移的参考偏移。合法且未受限的输入按原版直接位置语义及0.3mm重复过滤处理，不执行逐周期速度积分。仅在发送成功、拒绝或保护裁剪/保持时更新偏移，受限位移不在后续追赶。跟不上时实际总位移仍可能小于设置比例，末条已发目标仍可能造成残余运动。
- 松开即停发并销毁本次基准、未发送意图和残差；HDAPI 高频采样记录单调的 Button1 释放沿计数，以便33ms控制循环发现两次轮询间的快速松开再按下。若本次离合曾成功本地发送运动指令，主动请求一次已有 ResetRobot 软件停止；未下发运动的离合不请求 ResetRobot。收到成功应答后，仍需三次不同的后续有效空闲反馈（实际关节/线速度及模式），方可重新抓取。RunQueuedCmd 不是队列深度，不能单独证明有/无待执行命令。提前重按不自动开始运动，但等待期间可以累计停稳反馈，确认后松开再按不必重新累计。停止确认失败、反馈失效或超时退出遥控并走原异常停止路径。软件停止并非物理急停，不能保证立即制动或中转站无积压。
- 当前会话真实控制时轴向、比例和死区在 UI 中锁定；启动确认显示实际选项而非硬编码默认值。

## 单一生产路径与限制分层

DeviceController 默认 ServoP 路径使用 FixedAxisServoP，旧 RelativeServoP 只为离线历史回归保留，不再进入应用的实际控制路径。删除旧速度/反馈档位 setter 和运行中的旧软跟踪仲裁分支。FixedAxisServoP 只处理当前离合、纯轴向映射、独立指令安全仲裁；raw intent 与实际发送目标分别记录。只在本地 TCP 写成功后确认候选；此确认不代表机器人已经执行。

安全限制与映射分离。取消旧版 60/120/180mm 单次离合总行程球面限幅。按住 Button1 持续移动时，离合基准仅定义坐标原点，不再限制相对该点的总距离。现有软件实验 XYZ 范围、20mm 单次目标变化/目标超前、25mm 已发目标跟踪异常门槛保持。不能把这些数值称作已认证速度、加速度、工作空间或停止距离。一个轴因软件范围被保持时，在未发包的帧中也显示其原因；其他轴仍按现有仲裁检查。受这些约束时实际发送目标可能与 raw intent 不同，仍会出现跟踪等待。不能宣称完全恢复旧版速度或无约束运动。

当前硬件反馈优先处理：8891 机器人状态、错误、使能、模式、实际 TCP/关节状态和会话持续监控；30003 ServoP 非零错误通过 relay master 转回，由现有控制器停止路径处理。硬件本身也执行其内部安全限制，但当前协议没有提供完整的经核实的硬件安全工作空间/关节限位配置、障碍物信息或停止距离，因此不自动扩大/取消软件范围，不自动回位，不把“未报告错误”视作安全证明。Y=-413.58mm 启动拒绝仍适用，直到现场确认并按实际设备配置审定新的软件安全范围。设备自身 HDAPI 校准健康检查保留（不等于两设备间严格标定）。

## 验证

tests/fixed_axis_servop_tests.cpp 覆盖 48 种带符号轴映射、2×位移、首帧零下发、提前重按、独立新基准、重复遥测序号、配置变化、保持原始意图但不突破指令包络、软件边界诊断，以及同一次离合连续越过原 60mm、180mm 行程上限的 300mm 模拟跟随（仍受原指令包络和绝对软件空间检查）。新增到 C++17 离线 CI；旧控制测试仍保留。Windows Qt 完整构建、实际物理方向、实际停稳时间和运动表现未验收。没有改变中转站 master、早期视频分支、ServoJ/MovL 的控制算法、机械臂固件或安全参数。实际设备试验必须由现场人员在已核实的工作区域和独立物理急停条件下进行。

### 单次离合行程限制移除

用户现场确认控制改善，但按住 Button1 连续移动时达到某个相对距离后目标停止推进，松手重新抓取才可继续。根因是原 FixedAxisServoP 的 m_travelMm 球形裁剪（默认60mm，最大180mm）。现已删除该裁剪、配置入口、对应 Qt 控件与饱和日志。历史 RelativeServoP 及其离线测试、独立 ServoJ/MovL 实验约束保留。此次没有扩大绝对软件工作空间，没有提高单次指令跳变或实际TCP超前距离、跟踪误差停止门槛，也没有改变硬件异常或反馈失效停止逻辑。新增的300mm用例为理想跟随模型中的纯算法回归，不代表实机轨迹已经通过安全评估。持续按住的可运动总行程增加，需现场重新确认操作区域、物理急停及实际停止性能。

### 同步优先与松手停止改动

本轮针对拖尾、短时间松手重按无响应及顿挫，修改 FixedAxisServoP 为新位移消费而非绝对终点追赶。增加释放沿计数、一次正常释放停止请求、ACK之后不同序号停稳反馈门禁和对应状态日志。已有跟踪错误/软件工作空间/20mm单条指令约束、33ms运动定时器、8891时效及独立物理急停要求不变。ServoP 模式下 UI 采样展示周期改为66ms，退出或软件急停恢复33ms；Touch 高频采样不变。Qt控制/反馈尚未迁移独立工作线程。本轮新增纯算法回归覆盖超出包络的旧位移不重放、暂停无下发、反向、低速微位移、ACK前不重抓、快速释放再按、无运动离合免软件停止。实际制动、固件停止行为、机械臂动态速度和 Windows Qt 完整构建均需现场确认，不能视为已恢复原版速度。

### 恢复 master 式直接位置、独立控制事件循环与固定轴旋转预览

用户再次确认 master (894ff8f) 的现场控制更流畅，要求保留新轴映射、比例和离合并恢复原版底层控制风格。核对原版每33ms取 Touch、相对位置映射、0.3mm重复过滤、8888→30003六参数ServoP写入；不复制硬编码RPY(150,0,90)、缓存GetPose当作新鲜基准或缺失的反馈异常保护。

- 当前 FixedAxisServoP 不再使用上一轮逐采样增量累加及残差状态；正常帧以固定轴直接位置为目标。因现有独立工作空间/20mm包络限制而丢弃的位移，通过调整参考偏移消化，不生成历史补偿队列。按下不运动、松开主动软件停止、停止应答及实测停稳、释放沿计数、25mm跟踪异常停止、工作空间及硬件/遥测保护均保留。底层仍复用原式六参数 ServoP 文本、30003端口和TCP写入；不调整机器人固件速度或网络/中转站。
- TeleopControlThread 同时拥有 DeviceController、运动定时器、8891 RelayStateClient 及其 socket/watchdog。GUI 不直接调用跨线程变更方法，操作请求以 queued connection 提交；校准对话框仅读取 Touch 原子快照和有单调时效的遥测缓存。实体模式状态供GUI读取为原子值。退出时先停止/断开后端和移除回调，再关闭控制线程。视频网络线程与OpenGL UI线程保持独立。该设计不是硬实时，阻塞TCP写入、控制器执行和操作系统调度仍可能产生延迟。
- 新增“固定轴六维预览（只读）”：使用同一轴映射和平移比例；旋转取 R_h * R_h0^T，再用 M * ΔR_h * M^T 转到机器人坐标，左乘抓取时机器人姿态。旋转角度独立为1:1，欧拉角选择接近上一帧的等价分支，拒绝奇异或无效姿态。即使轴置换包含反射，旋转矩阵仍保持正交且行列式+1。这里采用已有ZYX预览约定，尚未验证本机控制器的实际RPY定义和旋转路径/关节限位。**仅生成和显示六维目标，不发实体旋转命令；实体ServoP仍锁定原抓取RPY。**
- 新增 Qt 实际控制/主窗口翻译单元编译检查和本地 TCP 模拟遥测线程回归（GUI 阻塞期间 worker watchdog 应独立失效）。这不是完整 Windows Qt/OpenHaptics 链接、真实机械臂速度或旋转安全验收。20mm/25mm约束仍可能限制运动灵敏度，本轮不宣称与 master 物理表现完全相等。
