# 通信与失联保护改动（2026-11-28）

## 协议与行为

- 客户端连接中转站后立即发送 `29999|RelayHeartbeat()`，之后约每 100ms 续期。该消息只由中转站消费，没有机器人命令或普通回复。旧客户端没有心跳时，新中转站拒绝运动；两端应配套更新。
- 中转站要求运动前心跳不超过 500ms、三条机器人端口在线、反馈有效且不超过 500ms、机器人已使能且无错误/拖拽/暂停。后台每 20ms 检查，不依赖 Touch 主动发送停止。
- ServoP/ServoJ 仅保留一个待发目标，同一次接收中的旧目标被新目标替代。每 20ms 检查发送，目标自中转站接收起超过 100ms 即失效。下游 Qt 待写数据未排空时不追加连续目标，持续超过 100ms 触发保护。
- 这些期限是软件调度条件，不是硬实时保证；已进入操作系统或控制器的字节不能通过清空应用队列撤回。异常时会中止运动 TCP 并独立发送 ResetRobot，不能以“本机写成功”代替机器人执行确认。
- 客户端采用非阻塞 Winsock，整条消息所有分段共享 100ms 写入截止时间。失败后 shutdown 该连接，不将半条消息与后续命令拼接。连接阶段等待上限 2 秒（域名解析不在此期限内，部署使用 IPv4 地址）。
- 发送超时或中转站 `ERROR|...` 会关闭客户端通路，接收线程发出断线事件。重连前会回收旧线程，即使 connected 已变为 false。

## 停止与恢复

- 控制客户端断线/替换、已建立的遥测客户端断线/替换、机器人端口断线、心跳/反馈超时和运动写入积压，触发停止屏障。
- 清除未发运动目标，关闭旧运动流，建立干净的 dashboard 流发送 ResetRobot，防止停止排在旧 dashboard 请求后面。未收到成功停止应答时每约 3 秒重新建立通路并重试，期间不授权运动。
- 成功停止应答仍不足以解除屏障：必须看到更高反馈序号、有效新鲜的 mode=5、非运行/排队/拖拽/点动/错误状态，TCP 和关节反馈速度绝对值均低于 0.1。原客户端断开后需用户重新连接和启动遥控；从不重放旧目标。
- 正常离合释放仍发送既有 ResetRobot，并等待停止确认。无积压时保持运动 TCP 连接，避免正常松手导致遥控模式退出；有积压时按故障处理。待发目标在停止前清空，停止屏障内拒绝新目标。
- 8891 命令入口限制为 RobotMode/GetPose/GetAngle/GetErrorID/InverseSolution 等诊断读取，不能作为另一路运动或使能入口。
- 中转站退出只做有界的尽力停止发送；中转站进程/电脑断电、机器人网络完全不可达时，软件无法保证物理停止，需要机器人侧通信看门狗/硬件保护。500ms 的软件期限不代表实测制动时间。

## 离线测试

中转站（Qt/MSVC 路径可传参）：

```powershell
.\relay_station\tests\run_offline_tests.ps1
# 可选：-QtRoot C:\Qt\6.11.0\msvc2022_64 -VisualStudioRoot 'C:\Program Files\Microsoft Visual Studio\18\Community'
```

客户端（Windows MinGW g++）：

```powershell
.\TouchControlPanelSolution\tests\run_offline_tests.ps1
```

两者均支持 `-BuildOnly`。网络测试只使用 127.0.0.1 模拟服务；执行环境须允许本地 TCP，不需要摄像头、Touch 或机械臂。

新增覆盖：无心跳拒绝、最新目标替换、目标过期、客户端失联、反馈失联、普通停止取消待发目标、ACK 不等于停稳、恢复不重放、静止持笔续期、下游拥塞、停止失败重试、实际 Winsock 分段发送/超时，以及真实 CommunicationBackend 的心跳、拒绝响应、断线和重连。

本次验证结果：中转站 77/77 项通过；客户端 18 个独立测试程序加 1 个真实通信后端集成测试，共 19 个程序通过。正常离合释放后，同一连接恢复操作有专门回归用例。Winsock 堵塞模拟约 110ms 返回失败（含调度及测试开销）。未连接实体机械臂，也未将离线结果视为实机制动性能验收。

后续已增加默认关闭的棋盘格平面测距观察模式，见 relay_station/docs/VISION_OBSERVATION_PLAN.md；摄像头作为受保护工具，自动回弹仍未接通。通信保护不依赖视觉结果。
