# TouchControlPanel：遥控控制收口与实机验收

本轮范围固定为两个目标：**受控单步**与**连续遥控**。不再增加标定系统、摄像头或 ServoP 对照工作。

## 共用输入与界面

- 已验证的 Touch XYZ、姿态和按钮读取不变；机器人实时反馈取自 8891。
- 左侧保留初始化、连接、急停、六维 Dry Run、平移轴映射、比例、死区、单步与连续控制。机器人管理和 8891 独立管理默认折叠，失效的视频占位按钮移除。
- 标定及 GL 显示辅助功能、右侧 TCP 原始收发报文默认折叠。
- 六维 Dry Run 不要求保存空间标定；使用固定默认轴映射。姿态 ZYX 假设仍未在实际机器人上独立验证，**实体运动目前只使用 XYZ，机器人 Rx/Ry/Rz 保持不变**。
- 不使用旧 ServoP。中转站 `relay_station/master` 不需要变更；实体运动经 Legacy 8888，实时反馈经 v2 8891。

## 目标 1：受控单步（MovL）

1. 先仅用平移 Dry Run 逐轴验证方向；默认方向采用主分支 XYZ 对应关系，比例 1.0、死区 0.3 mm。正式试动前仍需逐轴核对方向。
2. 将机器人通过现场受控示教置于已知无障碍的安全位置，确认外部物理急停可用；启动 8888 + 8891，观察 `Mode=5`、使能、无拖拽/报警，检查 User/Tool 正确。
3. 点击「启用平移预览」，按住 Touch Button1 缓慢移动，点击「执行单步（确认）」捕获候选目标。单步命令最大 3.0 mm，距本次离合捕获位置不超过 15 mm，保留机器人实际 Rx/Ry/Rz。
4. 阅读二次确认框，确认本次位移的轴向和具体坐标；再点击确认，才向 30003 发送一条低速 `MovL`。
5. 控制器首先等该指令的普通应答，再通过新鲜 8891 反馈检查机器人是否实际停稳到达。**应答成功不是已到位**；收到失败、失去反馈或超时，将停止继续执行并请求 `ResetRobot()`。
6. 单步完成前不会自动发送下一条运动。只有独立验收单步响应后，才进入下面的连续实验。

## 目标 2：连续遥控（InverseSolution + ServoJ）

1. 必须先在当前 8891 会话里完成一次有应答且实际到位的单步验证；若 8891 断开重连、触发急停或切换拖拽/下使能，将清除本次单步验证状态。在同一安全位置单独点击「连续遥控 ServoJ」并确认风险提示。
2. 按住 Touch Button1 捕获本次相对起点；后续仅将 Touch XYZ 位移转换为机器人 XYZ 目标，并保持机器人当前姿态。
3. 以约 33 ms 的控制计时器发起最新的 `InverseSolution` 查询，就近选择关节解；同一时间最多一个 IK 请求在途。对已通过验证、年龄不超过 180ms 的最新关节目标允许 33ms 重发，绝不重发更旧的目标。检查关节解相对于最新实际关节角的连续性与本次参考关节角的偏差，再将有限幅的关节目标下发 `ServoJ`。
4. 本轮实验将每次离合的目标位移软限幅在距起点 15 mm 内（超出后保持限幅目标，不自动重置机器人），每个 IK 目标相对最新 TCP 位姿最多前进 1.2 mm、每关节给定步长最多 0.35°。这些只是实验阶段的局部限制，**不是机器人型号特定的碰撞/奇异点安全证明**。
5. 松开 Button1 会停止本次离合并等待 `ResetRobot` 应答以及 8891 实际空闲后重新待命；主动停止、错误、离线、延迟逆解或反馈过期则终止模式；当已经发出运动时，通过 dashboard `ResetRobot()` 请求停止并清理队列。软件停止不是物理急停；操作员必须检查实体是否停下，不能仅凭按钮状态判断。窗口在实体模式运行时被关闭，会先请求停止并要求确认。
6. ServoJ 没有普通成功回包；以 8891 实时机器人状态为实际运动依据。实际频率会受到 8888 往返时延与 IK 回复速度影响，并不保证 33 Hz。

## 对照 master ServoP 的短行程 / 快速退出修复

这次只修复影响原目标的差异，不恢复 ServoP，不增加标定和新硬件：

- `master` 的 Touch 映射为 `机器人 XYZ = (Touch X, -Touch Z, Touch Y)`，增益 1.0。曾经新增的手动预览默认值是 `(+X,+Y,+Z)`、增益 0.25、死区 1.5mm。现恢复主分支方向，增益 1.0、死区 0.3mm。若现场惯用不同方向，仍可手动调整。
- 单步原来被限制为 1mm，且 `MovL` 使用 `SpeedL=1,AccL=1`、只有 4s 到位期；新上限为 **每次 3mm**、`SpeedL=10,AccL=10`、最多 7s 等待新鲜到位反馈，仍只允许一个在途运动。按新速率测试前先核查机器人安全位置和物理急停。
- `master` 每 33ms 直接发送最新 `ServoP` 目标，新的 ServoJ 需要先请求远程 `InverseSolution`，真实发送频率可能受 RTT 限制。现在单一 IK 在途，允许同一个**经过校验且不超过 180ms 的关节目标**按 33ms 重发；不重发更旧目标。提供每 2 秒 `IK请求/s` 与 `ServoJ下发/s` 统计。
- 离合释放原先仅停止发送并等待下一次按键；后期实现则直接终止整个连续模式。现在释放后会请求 `ResetRobot`，等待其应答和 8891 证实空闲，才重新待命；之后无需重复点击「连续遥控」即可再按 Button1。15mm 是**单次离合目标**的软上限；到达后可保持 Button1 让机械臂继续接近限幅目标，松开 Button1 时才通过现有停机流程等待确认后重新抓取基准。
- 连续反馈门禁使用 Mode 5 或 7、使能、无错误/拖拽/点动、8891 数据新鲜和关节逆解连续性；不会因为 `Queued=yes` 拒绝。失效日志新增 Mode、反馈延迟、IK耗时和逆解相对实际关节/起点的偏差，避免所有失败都输出同一句提示。
- 原本单步 `MovL` 使用字节级完整命令回显比较，机器人如果规范化浮点精度或省略可选参数，就会因误判应答不匹配而超时停止。现在比较回显中的目标六维数值、允许 0.02 范围内的格式化差异；不把普通命令应答视为实际到位。
- **限定事实**：这些变更恢复输入方向和合理更新节奏，不证明机械臂本身已经正确跟随。远程 IK 往返若很慢，将在统计中体现；Windows Qt 编译和真实 ServoJ 停止行为仍需本机验证。物理急停必须独立可用。

## 20:33–20:34 实机反馈的定点修复

- `MovL` 成功应答不代表完成；旧日志在同一秒内称「已确认到位」，缺乏计划位移、真实位移和持续停稳证据。现在单步准备输出 `[STEP PLAN]`（机器人实测起点/Touch Dry Run 目标/限制后的 3mm 内目标），执行结束输出 `[STEP VERIFIED]`（实测终点、真实走过距离、误差、耗时和 seq）。到位须有至少 150ms 经过，且随后连续 3 个更新的 8891 反馈序号满足位置/静止要求；无法确认则输出实测距离和剩余误差，并且**不**放行 ServoJ。
- 当前「最大单步 3mm」是独立的运动验收步进，不会直接追随 Dry Run 中几十毫米的完整目标。因此即使预览显示了大位移，每次 `MovL` 最多也只移动 3mm；新日志能直观展示两者差异。
- `ServoJ` 原来在任何一帧 `Touch有效=0` 时永久退出，用户故障日志示例中 8891 反馈 0ms、机器人使能且空闲，**没有发出运动指令**。检查发现 `TouchBackend` 曾将 XYZ 有效性与姿态矩阵有效性绑定；此外 1kHz HD 生产者与 Qt 多原子快照读取会偶尔出现单次竞争失败。现在 xyz 有效性独立取决于 XYZ 有限值；手动 XYZ 预览不再需要 Touch 旋转矩阵。
- 连续控制将孤立的一次无效 Touch 快照视为**本周期不发送**，不会继续发送旧 ServoJ 目标；连续 3 个控制周期无有效 XYZ 或无新增采样则停止并诊断，HD 调度器停止、校准失效、8891 断开仍会立即中止。
- 控制阶段输出 `[SERVO RATE]` 每 2s 报告 IK 请求/成功次数、ServoJ 发送频率、Touch 映射位移与末端跟踪差，即使输入死区导致没有运动请求也会报告。该输出用于识别是否实际上进入在线指令阶段，而不表示真实运动已经可靠。

**验收建议**：先在不使机器人运动的 Dry Run 重新验证 Touch 输入有效率。单步需根据 `[STEP PLAN]` 和 `[STEP VERIFIED]` 核对实际走过的距离；若仍没有 `[STEP VERIFIED]`，不要启动连续模式。Windows Qt/OpenHaptics 集成与真实机器人行为并未由 Linux 离线测试覆盖。

## 20:50 实机连续遥控被立即 ResetRobot 的根因与修复

- 单步真实运动已经通过：`[STEP VERIFIED]` 报告计划 3.000mm，实际 3.064mm，剩余 0.066mm，耗时 418ms；不应再将单步列为无法运动。
- 连续模式刚捕获 Touch 基准，手柄正常移动很容易超过 15mm 的临时行程包络：原程序随即发送 `ResetRobot()`，等待停稳后反复重新捕获。你记录的 `IK请求=0.5–0.7/s` 和 `ServoJ发送=2–2.5/s` 是这类**极短离合时间与反复重置**下的混合平均值，不能用来认定稳定跟随的正常速率。
- 保持原来的 **15mm 单次离合行程上限**，但把超限处理由“立刻 ResetRobot”改成“将目标沿位移向量缩放到球形 15mm 包络”。限幅发生一次时显示 `[CLUTCH LIMIT]`，只在松开 Button1 或真正异常时走停止流程。此改动并未扩张实际允许的目标范围。
- 此控制器的 `ServoJ` 尽管无需同步等待，却实际向 Legacy 通道回显了 `0,{},ServoJ(...);`，此前消息被误认为 `InverseSolution` 或 `ResetRobot` 的异步回复并持续刷屏。现在忽略正常成功回显；非零错误码会记录并终止当前 ServoJ 模式。依旧依据 8891 验证实际运动。
- 新 `[SERVO RATE]` 区分 Touch 映射原始位移、15mm 软限幅后目标位移、8891 机器人相对本次离合起点的实测位移以及目标剩余误差，帮助识别软件限幅与机器人真实跟随延迟。先在物理急停可用、无障碍工作范围内核实是否能平稳接近 15mm；若仍发生意外停止，需保留新的具体终止日志。

## 验收前必须区分

- **离线 CI 通过**：仅表明数学、输入、分帧测试通过。它不能证明 Windows Qt/OpenHaptics 编译通过，也不能证明 CR3 机械臂执行安全。
- **Windows 手工构建与软件检查**：先不开实体运动，确认两个预览模式、轴映射、图形渲染和所有状态字段。
- **实体单步试动**：由现场人员在清空的工作空间内、使用真实物理急停和独立示教确认后执行。任何偏向、延迟停止、异常加速或机械臂报警，都应终止本轮测试。
- **连续试动**：只在单步行为通过、机器人固件确实支持当前 ServoJ 指令语法及停止行为已确认后进行，先保持小范围、短时、低比例输入。

当前真实 ServoJ 跟随与绝对关节范围、奇异点附近行为、失联时硬件停机能力仍须现场独立核实。这些风险不能通过代码里存在一个数值限幅来视为已经解决。

## 21:04 连续控制被 RelayAge=501–511 ms 中断：定点修复

实机日志：`[STEP VERIFIED] 计划3.000mm 实际3.031/3.042mm，误差0.034/0.044mm，耗时419/474ms`，说明单步 MovL 已确实执行。连续 ServoJ 在 `Mode=7, Running=1, Enabled=1, Error=0, FeedbackAge=31/41ms` 时停止，原因是本地 `relayStatusAgeMs>500ms`，观察值分别为 **511ms 和 501ms**。机器人实时 `robot_state` 并未过期。

实际 `relay_station/master` 的 `relay_status` 使用 **200ms 定时发布**，且在拥塞时可能延迟/合并状态元数据；它与高频 `robot_state` 是不同数据流。修复：

- 连续模式的高频机器人反馈上限保留为 **250ms**，中转站状态心跳上限改为 **750ms**，与 `RelayStateClient::hasFreshState()` 所用默认 gate 一致。**不**忽略 `relay_ready=false`、缺失端口、会话变化、无使能、模式不符或实际机器人状态超时；收到即时状态故障仍终止运动。
- `RelayStateClient::refreshStatus()` 原先每收一帧机器人数据都向 Qt 发包含不同 `seq` 的 `statusChanged`，造成不必要的 UI 频繁重绘。现将标签限频约 5 Hz，**不**降低机器人快照/新鲜度检查的采样频率，状态类别变更即时发信号。
- 退出日志增加 `RelayReady` 和三个端口标记；`[SERVO RATE]` 增加 `RelayAge`，验证是否仍存在心跳延迟。离线回归测试覆盖 501/511/750ms 不误停、751ms 停止，以及机器人反馈251ms、端口断开和 relay 未就绪时禁止继续。

这轮不改变 IK 算法、关节幅度、15mm 离合软限幅或 ServoJ 命令周期。**离线 CI 不能证明 Windows Qt 构建与实机连续跟随通过**。实机复验时观察是否不再在约半秒内因 RelayAge 超时停止；若连续运动可持续，再根据 `SERVO RATE` 和实测 TCP 位移判断跟随瓶颈。物理急停须保持可用。
